 bw --version

1. Store API keys in Bitwarden as secure items.
 Suggested item names:

 ◦ OpenAI API Key
 ◦ Anthropic API Key
 ◦ Brave API Key

1. Find each item ID:
 bw list items --search “OpenAI API Key”
 bw list items --search “Anthropic API Key”
1. Add exports to ~/.zshrc or the shell file OpenClaw Gateway uses.
 Important: bw normally needs a session token after unlock. Use BW_SESSION.

 Example:

 export BW_SESSION=“$(bw unlock --raw)”

 export OPENAI_API_KEY=*** get password “OpenAI API Key” --session “$BW_SESSION”)”
 export ANTHROPIC_API_KEY=*** get password “Anthropic API Key” --session “$BW_SESSION”)”
 export BRAVE_API_KEY=*** get password “Brave API Key” --session “$BW_SESSION”)”

1. In ~/.openclaw/openclaw.json, ensure this exists:
 “env”: {
 “shellEnv”: {
 “enabled”: true,
 “timeoutMs”: 15000
 }
 }

1. Verify the shell can load the key:
 zsh -lc ‘test -n “$OPENAI_API_KEY” &amp;&amp; echo OPENAI_API_KEY_OK’

1. Restart OpenClaw Gateway:
 openclaw gateway restart
 openclaw gateway status

1. If the gateway starts from launchd and cannot unlock Bitwarden interactively, use one of these:
 ◦ Prefer: configure a Bitwarden machine/service auth method if available in your environment.
 ◦ Or: use a secure local env file generated at login from Bitwarden, chmod 600, and source that from the gateway shell.
 ◦ Avoid: putting raw keys directly into openclaw.json or tracked repo files.
Acceptance checks:
• openclaw.json contains no raw API keys.
• zsh -lc can see OPENAI_API_KEY.
• openclaw gateway status is healthy after restart.
• A new OpenClaw session can call the configured model provider without auth errors.
Main gotcha: Bitwarden CLI’s bw unlock --raw is interactive unless the machine has a non-interactive auth flow. If your gateway starts unattended after reboot, solve that part first; otherwise the env import is correct but the secret fetch will hang or fail.
