## Astro base path debugging

- Astro `base` config (`astro.config.mjs`) controls both dev server mount path AND static build asset paths
- Setting `base: '/astro-page'` means:
  - Dev server: the site is served at `/astro-page/` not `/`
  - Static build: asset references in built HTML get the prefix (e.g. `/astro-page/_astro/...`)
- If serving the static `dist/` directory at root level (e.g. via `python3 -m http.server -d dist/`), the baked-in `/astro-page/` prefix causes CSS/JS 404s
- Fix for static serving: either rebuild with `base: '/'`, or serve the dist directory under the `/astro-page/` subpath
- Changing `base` breaks the dev server URL — must restart the dev server after changing it
- Lesson: always verify BOTH the dev server AND the static server after base path changes. Check asset paths in built HTML match the actual serving setup.
- The site-audit Playwright tool (`node tools/site-audit/audit-site.mjs <url> <outdir>`) is useful for verifying the page actually renders with styles
